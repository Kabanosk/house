# You don't need long context (arXiv 2611.05306)

Belcak i in., NVIDIA, 3.11.2026. <https://arxiv.org/abs/2611.05306> (PDF:
<https://arxiv.org/pdf/2611.05306>). Notatka z 2026-11-16.

## Teza
Agent nie potrzebuje długiego kontekstu, żeby robić długie zadania. Wystarczy co jakiś czas zastąpić historię
krótkim „stanem” i czytać duże wejścia wybiórczo z plików. Dokładność prawie się nie zmienia, a koszt spada kilka razy.

Motywacja: koszt wygenerowania tokenu rośnie z długością kontekstu. Przy 256K zamiast 16K jest 3,6–7× drożej
(GLM 5.2, Kimi K2.6, Qwen 3 Coder Next na H100). Lokalnie (DGX Spark) opóźnienie między tokenami rośnie ~2×.
Cennik API tego nie pokazuje, bo cena za 1M tokenów jest stała.

## Jak to działa
Harness: mini-swe-agent (minimalna pętla ReAct, jedna komenda bash na turę). Trzy tryby zarządzania kontekstem:

| Tryb | Co robi |
|---|---|
| **FHA** (Full-History Accumulation) | baza: wszystko dopisywane do jednej rozmowy |
| **EoCC** (End-of-Conversation Compaction) | gdy rozmowa przekroczy próg (np. 24K z limitem 32K), model pisze „handoff recap”, harness startuje **nową** rozmowę: system prompt + oryginalne zadanie + recap |
| **SAC** (Single-Action Compaction) | skrajność: każda rozmowa = stan + **jedna** akcja + wynik → zaktualizowany stan → nowa rozmowa |

Długie wejścia (książka, raporty): zamiast wklejać, pliki w systemie plików + `grep`/`sed` + `doc-read`
(okno max 6–8K znaków) + instrukcja „czytaj tylko to, czego potrzebujesz”. To zamienia zadanie „długie wejście”
w zadanie „długi horyzont”, które już obsługuje kompakcja.

## Wyniki (Claude Opus 4.5, GPT 5.6 Sol)
- **Długi horyzont** (SWE-bench Verified/Multilingual, Terminal-Bench 2.1, FRAMES, τ²-bench, BFCLv3), limity
  16K–48K: zmiana dokładności −3,7…+5,6 pp, w ≤5/22 konfiguracjach strata >2 pp. Koszt (szacowany przy tańszym
  serwowaniu krótkiego kontekstu) 2,2–8,8× niżej. Najlepiej zwykle 24K–48K, najgorzej najciaśniejsze 16K.
  Przykład: SWE-bench Verified, Opus 70,0 → 74,8 przy 24K/18K.
- **Długie wejście** (LongBench v2, LOONG, AA-LCR, NIAH, RULER, Counting-Stars, BABILong): wybiórcze czytanie
  daje od −0,4 do **+40 pp**, koszt 4–233× niżej. Długość rozmowy prawie nie rośnie z długością dokumentu.
- **SAC**: SWE-bench Verified Opus 70,0 → 70,2, Terminal-Bench 47,2 → 51,8; GPT −2…−3 pp. Szczytowy kontekst:
  mediana 7–9K (zamiast maks. 130–200K).
- **Modele open-weight** (kwantyzowane, bez treningu pod kompakcję): różnie. Qwen 3.6 27B i MiniMax M2.7 trzymają
  wynik, Qwen 3 Coder Next przy 16K spada z 53% do 3,6% (za gadatliwy: między kompakcjami nie zdąży nic zrobić).
- Propozycja na przyszłość: **SSSM** (Semantic State Space Model): model trenowany do pracy na stanie w języku
  naturalnym zamiast na historii.

## Co robi dobra kompakcja (Appendix A)
Najważniejsze odkrycie praktyczne: kompakcja ≠ streszczenie. Streszczenie daje równą wagę wszystkiemu i przecenia
powtarzane fragmenty. Dobra kompakcja to **brief do dalszej pracy**, nie narracja historii:
1. zadanie dosłownie albo prawie dosłownie,
2. co agent teraz robi, co zamierza i jakie są następne kroki,
3. artefakty potrzebne dalej: plan rozbity na kroki, warunek ukończenia, fakty i wskaźniki do plików.

Prompt kompakcji z mini-swe-agent (Appendix G.1, dosłownie):

```text
Stop work. Write only a concise handoff recap; do not run commands or call tools.
The conversation will reset to the system prompt, task, and this recap.
{persistence}

Record:
1. Objective - one line describing the required result.
2. Established facts - exact paths, relevant symbols or commands, observed values,
   and important errors/output. Separate observations from unverified ideas.
3. Applied changes - each changed/created file, what changed, and whether verified.
4. Verification - exact checks run, outcomes, failures, obstacles, and workarounds.
5. Dead ends - failed approaches that should not be repeated.
6. Remaining plan - outstanding subgoals, in execution order; the immediate next
   command or edit; and the condition for completion.

{handoff_details}

If needed output was truncated, give a narrow command to retrieve it.
{submission_reminder}
```

## Zastrzeżenia
- Koszt w wynikach to „estimated optimized retail cost”: model zakłada, że dostawca policzy taniej za krótki
  kontekst. Według dzisiejszych cen API (nominal) oszczędność jest dużo mniejsza, czasem żadna (GPT na SWE-bench:
  $168 → $186–203, bo więcej nowych tokenów wejścia i mniej trafień w cache).
- Testowano autonomiczne zadania. Praca z człowiekiem w pętli (jego preferencje i poprawki) jest wspomniana tylko
  w Appendix A jako trudniejsza.
- Kompakcja jest stratna. Zadania, które wymagają dokładnej historii, rozwiązuje się zapisem całej historii
  i wybiórczym czytaniem, nie dłuższym kontekstem.
