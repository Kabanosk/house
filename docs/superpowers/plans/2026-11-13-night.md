# `house night`: fresh sessions, one task each (P4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `house night <contest>` works through ready tasks unattended: a preflight, then for each ready task a fresh headless worker session (Claude `claude -p --agent coder` or Codex) in its own worktree, the `house merge` gate, Signal answers and deadlines between rounds, circuit breakers, and a morning report.

**Architecture:** `houselib/night.py`: `preflight()` (pure checks returning problems), `pick_ready()`, `start_worker()` (builds the command, starts a subprocess with its own process group and a log file), `run_night()` (the loop; the session launcher is injectable so tests never start real agents). CLI `house night`. Reuses `checks`, `merge`, `guard`, `notify`, `inbox`.

**Tech Stack:** Python 3.11+ stdlib, `claude -p` (flags verified on this machine: `--agent`, `--settings`, `--permission-mode auto`, `--permission-prompts none`, `--model`; `claude auth status` → JSON with `loginExpiresAt`), `bin/codex-task`.

**Spec:** `docs/superpowers/specs/2026-11-12-system-hardening-design.md` §8 (P4) and §7a (permissions layer, Q2 = b).

## Global Constraints

- Workers never wait for a human: a hard decision becomes a Q-### and the worker ends the task as `blocked` (existing protocol).
- Sessions: `claude -p --agent coder --model sonnet --settings <contest>/.claude/settings.local.json --permission-mode auto --permission-prompts none "<brief>"` with `cwd` = the task worktree, `stdin` = `/dev/null`, own process group, stdout+stderr to `.house/tmp/night/<date>/<task>-<attempt>.log`. Task field `agent: coder-codex` (and Codex available) → `bin/codex-task <task file> <worktree>`.
- Per-session time limit: `spec.night.task_minutes` (default 45). Whole night: `--hours` (default 8). `.house/STOP` present → stop after the running sessions end (no new ones).
- Breakers: 3 failed attempts of one task → `blocked` + PROGRESS line; 5 failed attempts in a row overall → end the night (spec §8 rulings).
- Parallelism: at most `limits.max_parallel_agents` sessions; only tasks whose `depends_on` are all `merged`/`done`.
- Nothing ready and nothing running → end the night (spec §8, before P9).
- Every round: `house inbox` + `house deadlines` for this contest (answers can unblock tasks).
- Preflight refuses to start on: uncommitted tracked changes outside `.house/`, any red task in `house check --all`, free disk < 5 GB (warning < 10 GB), `claude auth status` not logged in or `loginExpiresAt` earlier than the planned end, missing `.claude/settings.local.json` (run `house adapt`), `.house/STOP` present. Codex not logged in → warning, Codex tasks fall back to `coder`.
- Morning: `reports/night-<YYYY-MM-DD>.md` (English: per task attempts, outcome, merge messages, log paths, questions raised), one Polish PROGRESS line, Signal summary via `house notify`, `.house/` committed.

## Review Focus

- A worker session that hangs → killed (whole process group) at `task_minutes`, counted as a failed attempt, worktree kept.
- A worker that leaves the task `doing` without commits → failed attempt; the task returns to `todo` for the next attempt (not stuck in `doing`).
- `house merge` refuses (red / guard / tamper) → failed attempt with the message in the report; reverted → task `blocked` (merge already did it), counted.
- Ctrl+C during the night → running sessions killed, report still written, `.house/` committed.
- Two tasks finishing at the same time → merges run one after another (never concurrently).

### Task 2: picking tasks and starting workers
**Produces:** `pick_ready(house, running: set[str], limit: int) -> list[str]`; `prepare_worktree(contest, task_id) -> Path` (creates `.worktrees/<branch without task/>` on `task/<id>-<slug>` from the contest checkout's HEAD when missing, sets `status: doing`, `owner`, `branch`, commits `.house/`); `worker_command(contest, task, worktree, tools) -> list[str]`; `brief(contest, task_id, worktree) -> str` (task file path, HOUSE_DIR, contest name, "one task; finish with house check GREEN and status review; hard decisions → Q-### and status blocked; never wait for a human").
- [ ] Tests: dependency order, limit, already running excluded; worktree/branch created once and reused on a second attempt; command for coder vs coder-codex (and fallback without Codex); brief contains the contest name and task path. FAIL → implement → PASS → commit.

### Task 3: the loop
**Produces:** `run_night(contest, hours=8, max_tasks=None, launcher=None, now=time.monotonic, sleep=time.sleep) -> NightReport` with `@dataclass Attempt: task, n, outcome, message, log`; launcher = callable `(cmd, cwd, log_path) -> Popen-like` (`poll()`, `wait()`, `pid`) so tests use fakes. After a session ends: worktree has commits beyond its fork point and status is `doing`/`review` → set `review`, `merge.merge_task`; otherwise failed attempt and status back to `todo` (or `blocked` when the worker set it). Writes report, PROGRESS, notify; handles KeyboardInterrupt.
- [ ] Tests with a fake launcher that commits a good change / a bad change / nothing / hangs: good → merged and counted; bad → merge red, attempts accumulate, third → blocked; nothing → back to todo; hang → killed at the limit (tiny limit in the test); 5 consecutive failures → night ends; STOP file honoured; report and PROGRESS written. FAIL → implement → PASS → commit.
